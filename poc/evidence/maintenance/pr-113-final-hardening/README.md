# PR #113 ForgeLoop Maintenance Evidence

## 1. Purpose

This evidence bundle publishes selected, cryptographically verified artifacts from the real ForgeLoop maintenance task used to implement and harden [PR #113](https://github.com/cassiomc1/forgeloop/pull/113) (`fix(poc): finalize cross-platform evidence verification`, merged at commit `43a5ee029b750aed01534f753e9523b96d7e0169`).

---

## 2. What this proves

This package contains independently auditable public evidence demonstrating that:

1. **Task Existence & Scoping:** A real ForgeLoop maintenance task (`poc-final-verifier-ci-hardening-20260826`, task key `e80ec0fe2c7166be2873291844c6ba619c751535b1c08f3e62b46c0f282ad21c`) governed all changes in PR #113 with explicitly declared write claims (`.github`, `package.json`, `package-lock.json`, `poc`, `scripts`).
2. **Contract Formulation & Preflight Gate:** The authoritative task contract (`source/contract.json`) formulated requirements R1–R8; guide routing selected `clean`, `test`, `documentation`, and `security`; and the security threat boundary gate (`source/gates/threat-boundary.json`) was satisfied before `preflight` evaluated `READY`.
3. **Append-Only Chronological Ledger:** The event ledger (`source/events.ndjson`) records 35 protocol events. The verifier recomputes each canonical SHA-256 event hash, checks exact sequence continuity and `previousHash` linkage, requires stable task identity, and confirms the terminal completion chronology.
4. **Transitive Execution Provenance:** All 6 completion checks referenced in the historical receipt have exactly one published execution derivative. The verifier closes the graph in both directions and cross-checks identity, requirement, argv, command, status, exit code, verification cycle, and timestamps. `FORGELOOP_EXECUTED` is preserved on the receipt checks.
5. **Validator-Backed Historical Completion:** The historical task reached `COMPLETE`, emitted `COMPLETION_VALIDATED` at sequence 34 followed by the `complete` transaction at sequence 35, and released its write claims. The preserved receipt is an intermediate `in-progress` / `not-verified` snapshot and is not treated as terminal proof.
6. **PR #113 Linkage:** The changed paths in the execution receipt match the exact 5 files modified by PR #113.

---

## 3. What this does NOT prove

- **Universal Correctness:** This evidence validates the execution and verification of the tested scenario only; it does not constitute a formal proof of universal correctness.
- **Production Readiness:** Production readiness is explicitly recorded as `NOT_VERIFIED` across all artifacts.
- **Private Original Contents:** Redacted derivatives carry SHA-256 commitments, but the public bundle cannot prove the undisclosed contents without later disclosure of the private originals.
- **Out-of-Band Remote Witnessing:** Remote CI can verify the published bundle, but it did not independently observe developer-local filesystem transitions in real time.

## 5. Historical Integrity & Isolation

- **Private Originals:** Source originals remain outside the public bundle in private ForgeLoop task state; original publication-inspection outputs are preserved outside the bundle in a local private Git safety reference.
- **Commitments:** Every redacted public derivative is labeled `NON_AUTHORITATIVE`; `manifest.json` and its `_projection` metadata repeat the original SHA-256 and exact redacted-field description.
- **Original PoC Evidence:** The original Real Execution PoC evidence under `poc/evidence/poc-20260826-real-execution/` was not modified or overwritten.
- **Post-Merge Drift Detection:** Publication-time protocol validation is `STALE` with `REPOSITORY_CHANGED`; strict audit is `STALE` with `E_PHASE_ARTIFACT_STALE`, `E_STATE_REVALIDATION_REQUIRED`, and `E_RECEIPT_PATH_MISMATCH`. These findings are preserved exactly and do not rewrite historical completion.
